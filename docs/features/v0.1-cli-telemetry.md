# v0.1 CLI, pytest plugin, telemetry, and review follow-ups

Scope doc for branch `feat/v0.1-cli-telemetry`. Completes v0.1: the `korrel run`
CLI, the pytest plugin, opt-in telemetry, and three v0.1-review follow-ups (a
tool-loop cap, a CI workflow, `.env` ignored). This document is the contract the
subagents build against. CLAUDE.md hard constraints and voice rules bind every
task here.

## Step 0 findings (evidence over memory)

Confirmed against the installed toolchain, not docs or recollection.

- pytest **9.0.3**, CPython **3.14.0**.
- Plugin registration: the `pytest11` entry-point group. pluggy's
  `load_setuptools_entrypoints("pytest11")` (read from `_pytest.config` in the
  installed tree) is what auto-loads installed plugins. korrel ships its plugin
  through `[project.entry-points.pytest11]`; no user-side conftest required.
- Discovery hook signature in this version:
  `pytest_collect_file(file_path: Path, path: LEGACY_PATH, parent: Collector) -> Collector | None`.
  Use `file_path` (a `pathlib.Path`); the legacy `path` argument is deprecated.
- `pytest.File.from_parent` and `pytest.Item.from_parent` are present and are the
  supported constructors. Options come from `pytest_addoption(parser, pluginmanager)`.
- Failing the session: the Item `runtest()` raises a custom `AssertionError`
  subclass; pytest exits non-zero on any failed item. Override `repr_failure` and
  `reportinfo` for output.
- CLI: stdlib `argparse`. No CLI dependency added.
- Telemetry: opt-in. On consent the sender posts a single content-scrubbed
  `run` event to the default public collector baked into `telemetry.py`;
  `KORREL_TELEMETRY_ENDPOINT` overrides the destination for self-hosting.
  `KORREL_TELEMETRY=0`, `DO_NOT_TRACK`, and CI detection disable it. At v0.1
  scope time no collector existed and the sender shipped inert; the default
  collector landed later (PR #6).

## Invariants (do not violate)

- Canonical transcript types in `types.py` (`Message`, `ToolCall`, `ToolFunction`,
  `ToolSchema`) are the v0.2 export contract. Do not change their shape or
  attribute names. The runtime containers in `runtime.py` (`Transcript`, `Turn`,
  `RunResult`) are not the export target and may gain fields.
- Rubric reward-function signature stays `(completion, info, **kwargs) -> float`.
- BYO keys. No key on a field, in a file, or in a log. Read from the environment
  at call time only.
- `openai` stays an optional extra. No new runtime dependency. CLI, plugin, and
  telemetry sender use the standard library only.
- Tests run offline with no keys. Anything that calls a provider is exercised
  through an injected fake.

## A. Tool-loop cap (sdk-engineer)

The inner `while assistant.tool_calls` loop in `runtime.py` is unbounded.

- Add `max_tool_rounds: int = Field(default=8, ge=1)` to `Scenario`.
- In `run_scenario`, bound the inner loop by a per-turn round counter. When the
  count reaches `scenario.max_tool_rounds`, stop looping, do not call the adapter
  again for more tool rounds, and record the reason.
- Record the cap on the runtime container, not on a canonical `Message`. Add
  `stop_reason: Optional[str] = None` to `Turn` and set it to `"max_tool_rounds"`
  on the capped turn. Do not inject a synthetic message into the canonical
  message list.
- The default of 8 is a constant; the per-scenario override lives on `Scenario`.

## B. `korrel run` CLI (sdk-engineer)

New module `src/korrel/cli.py`, wired as a console entry point
`[project.scripts] korrel = "korrel.cli:main"`. Subcommand structure with
`argparse` (room for more verbs later); `run` is the only verb in v0.1.

`korrel run <scenario.py> [--out DIR] [--seed N] [--scenario-attr NAME]
[--adapter-attr NAME]`:

1. Load the module from the file path with
   `importlib.util.spec_from_file_location`.
2. Read the `Scenario` from module attribute `scenario` (override
   `--scenario-attr`) and the `AgentAdapter` from module attribute `adapter`
   (override `--adapter-attr`). Clear error if either is missing or the wrong
   type. The adapter is BYO and calls the agent under test with the user's own
   keys; korrel holds none.
3. Run through `run_scenario(scenario, adapter, seed=...)`.
4. Write the transcript via a shared helper (see "Transcript output") and print:
   score, pass/fail, the failed rubric function names, the failure clusters, and
   the transcript path.
5. Exit non-zero when `result.passed` is false; zero when it passes.

Add a one-line adapter helper in `adapter.py` so example authors and users can
wrap a provider as an adapter without boilerplate:
`adapter_from_provider(provider) -> AgentAdapter` returning a callable
`(messages, tools) -> provider.complete(messages, tools=tools)`. This is a public
API addition, not a change to the canonical types or the rubric signature. Export
it from `__init__`.

## C. pytest plugin (sdk-engineer)

New module `src/korrel/pytest_plugin.py`, registered via
`[project.entry-points.pytest11] korrel = "korrel.pytest_plugin"`.

- `pytest_addoption`: an ini option `korrel_glob` (and matching `--korrel-glob`)
  selecting which files are scenario modules. Default `*_scenario.py` so it does
  not hijack ordinary `test_*.py` collection.
- `pytest_collect_file(file_path, parent)`: when `file_path` matches the glob,
  return a `pytest.File.from_parent` collector.
- The collector imports the module (reuse the CLI's loader), and for a module-level
  `scenario` + `adapter` yields one `pytest.Item.from_parent`. If `adapter` is
  absent, fail the item with a clear message (a scenario file in a CI gate must be
  runnable).
- `runtest()` runs the same path as `korrel run` and asserts
  `result.passed`. On failure raise a `KorrelScenarioFailed(AssertionError)`
  carrying score, threshold, failed functions, and the transcript path.
- `repr_failure` prints score, pass/fail, failed functions, and the transcript
  pointer. `reportinfo` returns the scenario location. It should feel like
  ordinary pytest: a green dot on pass, a normal failure block on fail.
- korrel's own suite must stay offline. test-author supplies fixture scenario
  files whose `adapter` is a scripted offline adapter, under a fixtures directory
  matched by an explicit `--korrel-glob`, so no live call happens in CI.

## D. Opt-in telemetry (sdk-engineer; security-reviewer gates before integration)

New module `src/korrel/telemetry.py`. Highest-risk surface. Everything is
best-effort and must never raise into the run path.

Consent and opt-out resolution, in order:
- If `KORREL_TELEMETRY` is set to a falsey value (`0`, `false`, `no`, `off`):
  disabled, no prompt.
- If `DO_NOT_TRACK` is truthy: disabled, no prompt.
- If CI is detected (`CI` truthy, or known CI markers): disabled, no prompt,
  default off.
- Otherwise, on first run with an interactive TTY, prompt once for consent and
  persist the decision. Non-interactive and undecided: treat as off, no prompt.

Persisted config: a small JSON file under an OS-appropriate config dir
(`%APPDATA%\korrel\config.json` on Windows, `$XDG_CONFIG_HOME` or
`~/.config/korrel/config.json` elsewhere). Stores the consent decision and a
randomly generated anonymous install id (uuid4, generated once). No key, no
scenario content ever written here.

Event (`run`) carries only:
- event type (`"run"`) and an event schema version,
- korrel version, python version,
- scenario count, total turn count,
- pass count, fail count,
- duration(s),
- the anonymous install id.

Never emit: scenario id or content, persona text, transcripts, prompts, tool
schemas, file paths, model names tied to a customer, or anything identifying.
The scenario `id` is customer content and is excluded.

Sender (pluggable):
- Resolve the destination: `KORREL_TELEMETRY_ENDPOINT` when set, otherwise the
  default public collector baked into `telemetry.py`. With consent granted,
  POST the JSON event with stdlib `urllib.request`, a short timeout, inside a
  try/except that swallows every error. Never block or fail the run.
- Under `KORREL_TELEMETRY_DEBUG` truthy, write the event JSON to stderr so it
  can be inspected instead of posting it to the collector.
- The sender is injectable so tests assert on the built event without any
  network.

## Transcript output (shared helper)

A single helper writes a transcript and returns its path, used by both the CLI and
the plugin: `Transcript.model_dump_json()` to `<out>/<scenario.id>.transcript.json`.
Default output dir: a `.korrel/` directory in the working tree (added to
`.gitignore`), or a CLI/ini override. The printed "transcript pointer" is this
path.
